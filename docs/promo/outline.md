# 主稿提纲（中文首发华为开发者社区 / 英文改投 dev.to）

> 目标：让"已经在跑 Hermes 网关的人"知道并愿意装 HermesPaw。
> 原则：**产品第一、技术第二**；技术只用来证明"这不是玩具"。所有数字都来自实测，可复核。
> 禁忌：不写公网/地铁/VPN 场景（本应用只做局域网直连）；不写内部 IP、主机名、企业系统名。

## 一句话定位（贯穿全文）

> 给已经在跑 Hermes 网关的人补一个手机客户端：人离开电脑、但还在同一个局域网时，能看 run 在做什么、
> 在 60 秒内批准一条危险命令、插话纠偏，或者直接停掉。

## 结构（5 节，技术占比约 20%）

| 节 | 内容 | 字数 | 承担的转化任务 | 证据来源 |
|---|---|---|---|---|
| 1 | **场景开头（第三人称·小明）**：季度经营分析会开到一半，他惦记着 Hermes Agent 正在跑的月度报表；`rm -rf` 清理历史报表目录触发审批，会议室没有电脑、回工位十分钟。引出"缺的是遥控器，不是又一个聊天窗口" | 300 | 让人对号入座；报表类任务是 agent 最典型的增效场景 | 真机审批实测（批准/拒绝/超时三条路径） |
| 2 | **为什么不用现成的企微/微信通道**：它们支持审批（文本式四选一），也确实好用——但审批被淹没在聊天里、窗口 300 秒、没有倒计时、打字确认。→ 分工而非替代 | 400 | 先打消"为什么不用微信"的疑问，建立可信度 | `docs/channel-comparison.md`（含源码位置） |

| 4 | **三步上手 + 演示 GIF**：网关出一条码 → 手机扫码 → 对话页显示「已连接」。强调脚本先自检、不通不出码 | 300 | 把"想装"变成"能装" | README 三步上手、`demo-zh.gif` |

结尾：仓库地址 + License（MIT）+ 边界声明（仅局域网、不做公网中继、不引入第三方 IM）。

## 三个必须写进去的"诚实点"

1. **它有明确的失效边界**：离开同一网段就用不了，这是设计取舍，不是缺陷。
2. **它不替代企微/微信**：人在外面、要推送，还是用 IM 通道。
3. **流式上屏做不到**：网关不推增量帧，所以等长回答时看到的是"已等待 N 秒"，不是逐字蹦字。

> 三条都在正文里主动交代——读者一旦自己发现，前面所有可信度归零。
